# FileSight — прогрес

Останнє оновлення: 2026-07-21 (після реальної перевірки ітерації 1).

## Поточний стан

Ітерація 1 завершена і перевірена вручну. Консольна програма сканує папку,
описує зображення локальною моделлю на CPU, генерує безпечні назви та пише
JSON-звіт. Файли не перейменовуються і не змінюються.

## Виконано

- [x] CLI `filesight scan PATH` та `python -m filesight scan PATH` (Typer).
- [x] Параметри: `--recursive`, `--output`, `--max-files`, `--language`,
      `--overwrite-report` (значення за замовчуванням — згідно з завданням).
- [x] Пошук `.jpg/.jpeg/.png/.webp` без урахування регістру; рекурсія опційна.
- [x] EXIF-орієнтація (`ImageOps.exif_transpose`) + конвертація в RGB.
- [x] Captioning на CPU: `Salesforce/blip-image-captioning-base`,
      автозавантаження та кеш Hugging Face.
- [x] Генерація назв: фільтрація вступних фраз, lowercase, дефіси, без
      заборонених символів Windows, ліміт 8 слів / 80 символів, збереження
      оригінального розширення.
- [x] Стабільна нумерація дублікатів у межах звіту (`-002`, `-003`).
- [x] JSON-звіт UTF-8 (schema_version 1.0) з помилками окремих файлів.
- [x] Пошкоджений файл не зупиняє сканування; Ctrl+C → частковий звіт.
- [x] 22 pytest-тести без завантаження реальної моделі — усі проходять.
- [x] README, docs/iteration-01.md.

## Фактична модель

`Salesforce/blip-image-captioning-base` (Hugging Face, BSD-3-Clause, CPU,
без `trust_remote_code`). Florence-2 відхилено: її remote-код несумісний із
Transformers 4.50+ (деталі та посилання — у docs/iteration-01.md).

## Перевірене середовище

- Windows 11 Pro for Workstations, CPU-only (без CUDA).
- Python 3.14.0 (замість запланованого 3.11 — у системі був лише 3.14;
  все працює, `requires-python >= 3.11` збережено).
- torch 2.13.0+cpu, transformers 5.14.1, pillow 12.3.0, typer 0.27.0,
  pytest 9.1.1.

## Результати ручної перевірки (2026-07-21)

Тестова папка `test-images/` (у .gitignore): реальна фотографія JPG,
JPEG, WebP, скриншот PNG, пошкоджений PNG, вкладена папка з дублікатом.

- 5 успішних файлів отримали caption і назву; пошкоджений записаний як
  `failed` з `UnidentifiedImageError`, сканування не зупинилося.
- Дублікат у вкладеній папці отримав суфікс `-002` (рекурсія працює).
- SHA-256 вихідних файлів до/після — ідентичні (нічого не змінено).
- Повторний запуск без `--overwrite-report` → помилка, exit code 1.
- Неіснуюча папка / шлях не до папки → exit code 2.
- `--language uk` → попередження про експериментальність, англійські назви.
- Швидкість: ~7–9 с на зображення на CPU (перший запуск + ~1 хв на
  завантаження моделі).

## Невирішені проблеми / відомі особливості

- Українські назви не реалізовано (лише попередження + англійський fallback).
- BLIP описує скриншоти загально ("screenshot of a computer screen ...").
- При першому запуску Hugging Face виводить власні попередження про
  symlinks/HF_TOKEN — нешкідливо, можна приховати змінними середовища.
- Прогрес завантаження моделі показує стандартний вивід transformers.

## Наступний рекомендований крок (ітерація 2)

Реальне перейменування за наявним JSON-звітом: команда `filesight apply`
з підтвердженням, dry-run та undo-журналом. Паралельно — покращення якості
назв для скриншотів і базовий український словник.
